### ❌ 丢掉的 —— ⭐ 这才是 2.0 要补的

**1. 【最致命】丢了「生存点」，把手段当成了目的**

> 原著：「**生存点不是数字，是你的呼吸频率、心跳次数、肌肉收缩强度——它记录你与世界的真实交互。**」
> 原著：生存点是「对环境适应度、资源转化效率、系统协同水平的量化表征」，
> 且「每一次升级均需 **材料 + 生存点双轨驱动**，杜绝无源之水式成长」。

- **原著**：资源 → 建成设施 → 结算生存点 → 生存点是真正的进度刻度
- **1.0**：资源 → 直接就是进度本身

**这就是 1.0 数值炸到千亿的总根。** 一旦资源本身即目的，它就只能无限累加；
而在原著里资源只是耗材，**真正的分数是周期性结算的「避难所状态」**。

> **⚠️ 2026-09-27 更正**：此前把「7 天」记成**结算周期**，**错了**。
> 原著原文是「**灾难周期性刷新一次，刷新前七天所有幸存者会收到预告**」——
> **7 天是天灾预告的提前量，不是结算周期。**
> 结算的真实描述是：系统「**评估基于生存环境，行为越积极，生存点越多，形成正循环**」，未见固定周期。
> 我们 1.0/2.0 原型里的「7 天一结算」是**自行设计的节拍锚点**，不是原著设定，别当成照搬。

**2. 丢了「每场天灾是一次针对性体检」**

> 原著：「**灾难不是敌人，是文明体检报告。酸雨检测防水能力，暴风雪考验保温系统，死潮验证社会韧性。**」

每场灾考核的是**一个具体的建筑/设施命题**（DEVLOG L210 记到了这条），
但 1.0 落地时退化成了 5 个一次性防灾设施 + 一个抽象防御数值的比对。

**3. 丢了具体的设施/家具清单**

原著前期逐样的升级顺序（目录可查）：

| 章节 | 设施 | 1.0 有没有 |
|---|---|---|
| 第 2 章 | 木门 → 铁门（衍生防盗/防辐射/防火三重属性） | 无（只做材质） |
| 第 3 章 | **饮水危机** → 幽能水井 | 无（水只是资源条） |
| 第 8 章 | **设计通风照明** | 无 |
| 第 9 章 | 培养基（种植） | 无 |
| 第 16 章 | **热食**（灶台） | 无 |
| 第 19 章 | **排水渠** | 仅抽象 `drain` 设施 |
| 第 32 章 | 柴油发电机 | ✅ 有 |
| 第 50 章 | **完美设计图 · 八项设施** | 无（无房具体系） |
| 第 53 章 | 工作台 | ✅ 有 |

**用户在 2.0 提的「冰箱保鲜、浴室清洁、水井产水、灶台做饭」——全部能在原著里找到出处**，
1.0 只剩下「工作台 / 装备台 / 发电机 / 储物箱」四个抽象功能件。

**4. 丢了「基建悖论」（互相制约的环形依赖）**

> 原著：造枪需钢 → 炼钢需电 → 发电需矿

资源链是**环形互相卡住**的，天然扼制单点膨胀。
1.0 的资源链是单向的（采集 → 制造 → 升级 → 数字更大），没有任何一环能反过来卡住产出。

**5. 丢了量级控制**

> 原著设施参数是**可感知的物理量**：「幽能井水提取器（精良）：**7200ml/天，300ml/小时**」

对比 1.0 的 838 万倍率、1763 亿钢。原著从头到尾是「七千二百毫升」这种人能想象的数字。

**6. 丢了维度跃迁**

原著后期不是「材质继续升级」，而是**避难所 → 地下城 → 文明 → 神域**（五次质变后整体升维）。
1.0 恰恰相反：材质链靠公式一路推到第 30 档 —— **这是背离原著的做法**。

**7. 丢了群像 / 支线**

原著四条并行支线：村民群像（猎虎/凤梦月/苏德本/康妮）、异族视角（矮人/鱼人/魔魂族）、
系统机制、灾变维度。还有以物换物+拍卖的交易体系、世界频道发言限制。
1.0 是纯单人单线。

## 二·五、原著的「系统」设定（2026-09-27 补，直接决定 2.0 的 AI 方案）

原著是**系统流**。苏摩首日绑定唯一专属的**「末日生存系统」**，它是全书的金手指与界面。

| 原著设定 | 出处要点 |
|---|---|
| **系统面板四大功能** | **【聊天】【交易】【制造】【物品】** —— 对话本来就是系统的功能之一 |
| **驱动核心** | **生存点**。系统「评估基于生存环境，行为越积极，生存点越多，形成正循环」 |
| **系统做什么** | 评估生存环境 → 反馈生存点 → **解锁新功能**（后期有监控、物质转换、灾难权柄） |
| **天灾预告** | 「灾难周期性刷新一次，**刷新前七天**所有幸存者会收到预告」 |
| **避难所核心** | 与系统是**两回事**。核心是物理存在（乌龟模样），有「美人鱼的水」「狮人的风」等超凡祝福，可融合扩展面积、解锁重构布局权限 |
| **世界之上还有「游戏」** | 废土世界受「游戏」系统调控，发布灾难、奖励权限；「世界核心」亚当是本土存在 |

**★ 对 2.0 的关键含义**

1. **AI 扮演「系统」是忠于原著的**，不是借壳。系统本来就会说话、会提示、会评估、会解锁。
2. **系统 ≠ 避难所核心**。建议拆开：AI 演系统（界面/提示/评估），核心是避难所里一个可升级的物理物件。
   这样避免「AI 就是一切」的过度集中，也让核心升级有实体感。
3. **系统从不替主角过日子**。它提示、评估、解锁，但挖井的是苏摩自己 ——
   这正好对应 2.0 的架构红线：**AI 出提案，规则引擎判定，玩家执行**。
4. **⚠️ 反面教训**：1.0 把系统做成了「说明书」（全部建筑摊开 + 连攻略一起给）。
   真正的系统应该**少说**——你做到了才告诉你下一步。

## 三、原著自带的「三个刹车器」（2.0 必须搬回来）

| 刹车器 | 机制 | 为什么能防数值爆炸 |
|---|---|---|
| **① 阶段性结算** | 每 7 天结算一次生存点，评分对象是「避难所状态」而非「库存量」 | 进度被周期性归零为一个分数，存量赚不到复利 |
| **② 双轨驱动** | 升级既要材料，也要生存点 | 单靠囤材料推不动，第二资源无法靠挂机刷取 |
| **③ 基建悖论** | 环形依赖（A 需要 B，B 需要 C，C 又回过来需要 A） | 任何一环都不能单独指数增长 |

> 补充：原著后期解决「水不够」靠的是**复制器**（每复制 1 吨水消耗 **100 灾难积分**），
> 即**用另一种资源兑换**，而不是把采集倍率乘以 838 万。这是第四种思路。

## 四、2.0 应照搬的原则清单

1. **目标是设施状态，不是资源存量** —— 资源是耗材
2. **每阶段一次结算** —— 周期性的分数，而非累积的大数字
3. **双轨（材料 + 积分）** —— 第二条腿不能挂机刷
4. **每场天灾考核一个具体设施命题** —— 不是抽象防御比对
5. **设施参数写成可感知物理量** —— ml/天、度、公斤，不要千亿
6. **后期靠维度跃迁，不靠同链条无限延长**
7. **环形依赖的资源链** —— 让每个系统都卡住另一个
